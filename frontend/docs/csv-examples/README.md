# CSV Export Examples

Пример формата CSV-выгрузок для модуля ребёнка в пользовательском виде.

Принципы этих примеров:

- без внутренних `id`
- без технических `foreign key`
- без сырых ISO timestamp
- с отдельными колонками даты и времени
- с человекочитаемыми заголовками
- без смешивания summary и детальных строк в одном файле
- без лишних повторяющихся единиц измерения в каждой строке, если это уже понятно из контекста

Файлы в этой папке:

- `analytics_summary.csv` — короткая сводка по ребёнку за выбранный период
- `child_care.csv` — повседневный уход: отдельные таблицы сна, кормления, веса и роста
- `child_illness.csv` — болезни, температуры и лекарства с контекстом ребёнка и периода

Текущая реализация:

- `Сводка` -> `analytics_summary.csv`
- `Уход` -> `child_care.csv`
- `Болезни` -> `child_illness.csv`
- `Все файлы` -> ZIP с тремя CSV или один XLSX с тремя листами
- все экспорты относятся к конкретному ребёнку
- отдельный `profile.csv` не нужен

## UI / UX

Рекомендуемое место кнопки:

- в профиле ребёнка
- под основной кнопкой `Редактировать профиль`
- вторичное действие в профиле ребёнка: `Поделиться CSV`
- текущий приоритет: iOS app wrapper
- PWA / desktop export UX сейчас не являются целевым первым сценарием

Ожидаемый пользовательский flow:

1. Открыть профиль ребёнка
2. Нажать `Экспорт данных`
3. В bottom sheet выбрать:
   - `Сводка`
   - `Уход`
   - `Болезни`
   - `Все файлы`
4. Выбрать период:
   - `2 недели`
   - `30 дней`
   - `6 месяцев`
   - `Всё время`
5. Выбрать `Сохранить CSV` или `Сохранить XLSX`

## Frontend Implementation Notes

Целевая точка входа:

- `src/client/pages/ChildProfilePage.tsx`

Что нужно доработать во frontend:

- entry point живёт в профиле ребёнка
- sheet позволяет выбрать тип данных, период и формат `CSV / XLSX`
- `Plus`-lock показывается прямо на кнопке в профиле
- при отсутствии `Plus` клик ведёт в существующий upgrade flow
- основной runtime — iOS shell с native share flow

Нужные UI-состояния:

- idle: выбор типа экспорта, периода и формата
- pending: подготовка файла
- success: короткий статус `CSV/XLSX/ZIP готов`
- error: понятное сообщение без технических деталей

## Product Rules

- экспорт относится к конкретному ребёнку, а не к глобальным настройкам
- summary и raw-detail export разделены
- `analytics_summary.csv` должен быть коротким и информативным
- `child_care.csv` должен читаться как журнал ухода без дублирующей summary-шапки
- `child_illness.csv` должен читаться как журнал болезни без дублирования слова `Эпизод` и без сырых кодов вроде `axillary`
- первый целевой runtime для реализации — iOS app wrapper
