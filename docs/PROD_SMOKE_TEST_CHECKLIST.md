# Production Smoke Test Checklist

Финальный короткий checklist перед production release и сразу после выкладки.

Цель:
- не повторять весь dev QA заново;
- быстро проверить environment-specific поведение;
- подтвердить, что family code, семья, подписка и ключевые экраны ведут себя так же, как в dev.

## 1. Family Invite

Прогнать основной сценарий:

1. `Plus owner` создаёт одноразовый код приглашения
   - код показывается в `Family`
   - код копируется без ошибок
   - срок действия отображается корректно

2. Новый пользователь открывает app и идёт в регистрацию
   - в форме есть блок `Есть код семьи`
   - код проходит `Verify`
   - показывается preview целевой семьи

3. Новый пользователь завершает регистрацию с валидным кодом
   - аккаунт создаётся сразу в target family
   - код повторно использовать нельзя

Дополнительно:
- битый/истёкший/использованный код должен показывать понятную ошибку
- ошибки кода не должны смешиваться с ошибками email/пароля

## 2. Family Member Removal

Проверить сценарий `owner -> удалить участника`:

1. Участник теряет доступ к текущей семье.
2. Аккаунт участника не удаляется.
3. Для участника создаётся новая пустая семья.
4. На втором устройстве участника сессия сбрасывается.
5. После сброса его ведёт на обычный вход, а не на промежуточный экран присоединения.

## 3. Family UI

Проверить:
- карточки участников семьи
- редактирование профиля участника
- меню профиля в шапке
- создание и копирование invite code

Особенно:
- тексты соответствуют реальной логике
- нет email/login там, где должны быть имя / роль / телефон
- карточки не содержат лишних дублей

## 4. Illness / Children Sync

Проверить кросс-девайс сценарий:

1. На устройстве A начать наблюдение по ребёнку.
2. На устройстве B дождаться появления активного наблюдения.
3. Проверить:
   - `Children`
   - `Журнал`
   - верхнюю навигацию / счётчик активных наблюдений

Ожидание:
- обновление не должно “зависать” на длинный интервал;
- второй девайс должен увидеть active illness за разумное время.

## 5. Subscription / Plus

Проверить минимум:
- `Plus owner` может создать invite
- аккаунт без подписки может вступить в семью с `Plus`
- owner/member removal не ломает billing guards
- family UI не даёт неправильных действий владельцу/участнику при активной подписке

## 6. Onboarding

После первого входа проверить onboarding:
- `Имя в семье`
- `Кто вы в семье`
- `Телефон`
- `Название семьи` для owner

Проверить:
- поля сохраняются
- overlay не ломает дальнейшую навигацию

## 7. Manual Pass Result

Перед релизом удобно зафиксировать коротко:

- `Invite`
- `Family remove member`
- `Illness cross-device sync`
- `Subscription / Plus`
- `Onboarding`

Формат:

```text
Invite: OK
Family remove member: OK
Illness sync: OK
Subscription / Plus: OK
Onboarding: OK
```

Если хотя бы один блок не `OK`, релиз не считать завершённым.
